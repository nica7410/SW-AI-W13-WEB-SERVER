# 12. 응답 중계 시간과 서버 종료 유예 시간에 상한 두기

외부 리뷰 1번 · 기준 커밋 `3a6b120` · 구현 순서 5/5

**구현 결과** · 짧은 전체 마감을 주입한 `test_proxy_relay`에서 본문이 계속 도착하는 중에도 전송이 중단됐다. 실제 서버의 `test_shutdown.py`에서는 SIGTERM 후 5.04초에 종료 코드 0과 CGI PID 회수를 확인했다. 수락 루프가 공통 종료 마감을 게시하고, 각 워커가 자신이 소유한 소켓과 자식을 정리하도록 구현했다.

외부 리뷰에서는 CGI가 계속 출력하고 클라이언트가 수신 중일 때 SIGTERM을 보낸 뒤 30초가 지나도 프로세스가 살아 있었다. 중계 코드는 본문 수신과 클라이언트 쓰기에 개별 I/O 타임아웃을 사용한다. 데이터가 계속 오가면 유휴 타임아웃의 조건이 성립하지 않는다. 종료 경로는 모든 워커를 `join`하므로 이 응답 하나로 종료도 지연된다. [본문 중계](../../../src/response_stream.c) · [CGI 회수](../../../src/cgi.c) · [워커 종료](../../../src/threadpool.c)

## 확정 범위

| 적용 구간 | 결정 |
|---|---|
| 평상시 CGI·Forward/Reverse Proxy 응답 | 응답 전체에 단조 시계 기준 30초 상한. CGI는 실행을 시작할 때, 프록시는 요청을 전달하고 응답을 읽기 시작할 때 한 번 정한다. 헤더, 본문, 마지막 쓰기까지 포함한다. |
| 진행이 멈춘 I/O | 기존 유휴 5초를 함께 적용한다. 프록시의 DNS부터 최종 응답 헤더까지의 공통 5초도 유지한다. |
| SIGINT·SIGTERM 수신 | 종료를 처음 인지하면 공통 유예 5초를 한 번 정한다. 진행 중인 응답은 남은 유예 시간 안에서 마칠 수 있고, 만료 시 남은 연결과 직접 실행한 CGI 자식을 회수한다. |

30초와 5초는 이 과제 서버를 위한 구현 기본값이다. 정상적으로 진행되는 대용량 프록시 응답도 30초를 넘으면 끊긴다는 동작을 README에 명시한다. 평상시 정적 파일에는 중계 상한을 적용하지 않으며, 서버 종료 유예는 정적 파일을 보내는 워커에도 적용한다.

## 구현 순서

1. **중계 전체에 같은 마감을 전달한다.** 기존 마감 API를 사용해 일반 본문, 길이 미지정 본문, chunk 크기·본문·트레일러, 클라이언트 쓰기를 모두 처리한다. 매번 새로 계산하는 유휴 마감과 고정된 전체 마감 중 이른 쪽을 적용한다. RIO 버퍼에 데이터가 남았거나 소켓이 계속 준비돼 있어도 마감을 확인한다. CGI 실행 결과를 알리는 파이프 대기와 출력 후 자식 회수도 남은 시간 안에 끝낸다. [마감 API](../../../src/deadline.h) · [CGI 실행](../../../src/cgi.c)
2. **오류 응답의 경계를 정한다.** 최종 응답을 쓰기 전 원 서버가 만료되면 504, CGI가 만료되면 기존 규약에 따라 500을 보낸다. 최종 응답을 일부라도 썼으면 두 번째 상태 줄이나 정상 종료를 뜻하는 마지막 chunk를 추가하지 않고 연결을 닫는다. CGI를 중단하면 직접 실행한 자식을 종료하고 `waitpid()`로 회수한다.
3. **워커를 기다리기 전에 종료 유예를 집행한다.** 시그널 핸들러는 기존처럼 플래그만 세운다. 서버 루프가 수락을 멈추고 모든 워커에 같은 마감을 알린다. 새 keep-alive 요청을 시작하지 않고, 유예 만료 시 큐에 남은 fd를 닫는다. 활동 중인 클라이언트·상류 소켓의 대기는 `shutdown()` 등으로 깨우고 실제 `close()`는 소유 워커가 맡는다. 워커의 등록·해제와 중단 요청을 동기화해 재사용된 fd나 이미 회수한 PID를 건드리지 않게 한다. CGI의 실행 대기·자식 회수, 요청 읽기, 정적 응답 쓰기, 프록시 연결 대기에도 종료 마감이 반영된 뒤에 워커를 `join`한다. [서버 루프](../../../src/server.c) · [워커 풀](../../../src/threadpool.c) · [연결 대기](../../../src/net.c)

## 완료 기준과 최소 검증

- **평상시 전체 마감** · 기존 `test_proxy_relay`에 짧은 전체 마감을 주입하고 유휴 제한 안에 계속 데이터가 오는 유한한 응답 하나를 사용한다. 중계가 전체 마감에 끝나고 일부 응답 뒤에 두 번째 상태 줄이 없어야 한다. 해당 실행 파일을 한 번 실행한다. [프록시 테스트](../../../tests/test_proxy_relay.c)
- **종료 유예와 자식 회수** · 실제 서버, CGI 하나, 수신 클라이언트 하나로 확인한다. CGI가 직접 자식 PID를 기록하고 유예 시간보다 길게 유한한 응답을 내도록 한다. 첫 본문을 받은 뒤 SIGTERM을 한 번 보낸다. 서버가 유예 시간에 짧은 스케줄링 여유를 더한 범위에서 코드 0으로 끝나고 CGI PID도 사라져야 한다. 정상 중계의 30초 상한이 먼저 끝나 우연히 통과하지 않도록 종료까지의 시간을 따로 측정한다.
