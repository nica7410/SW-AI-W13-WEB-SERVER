# 04. 큐가 가득 찼을 때 503 응답이 끝까지 전달되는지 확인

**작업 유형** · 진단 후 조건부 수정. 워커 8개와 큐 64개는 현재 기본 설정이다.

큐가 가득 차면 accept 스레드가 503을 쓰고 즉시 소켓을 닫는다. 파싱 오류를 처리하는 워커에는 송신을 닫은 뒤 입력을 제한된 시간 동안 정리하는 별도 경로가 있다. 외부 리뷰의 타임아웃만으로 어느 경로에서 무슨 오류가 발생했는지는 확정할 수 없다. [두 종료 경로](../../../src/server.c) · [큐 포화 정책](../../../src/threadpool.c) · [TCP 테스트](../../../tests/test_server_edges.c)

1. 리뷰의 원본 출력이 있으면 연결·읽기·응답 길이 오류와 HTTP 503 건수를 구분한다. 기존 기록이 없으면 원인 상태를 미확인으로 남긴다.
2. 실제 TCP 연결 한 쌍과 정상 요청 하나로 큐 거절 시 사용하는 처리 경로를 확인한다. 클라이언트가 503 상태 줄, 헤더 끝, `Content-Length`만큼의 본문을 모두 받았는지 확인한다. 본문 수신 뒤의 종료와 응답 중간의 리셋을 구분한다.
3. 응답 손실이 확인된 경우에만 거절 연결의 송신 종료와 남은 입력 정리를 수정한다. accept 스레드가 연결마다 워커용 정리 시간인 250ms를 기다리게 하는 방식은 포화 시 다른 연결의 수락까지 지연시킨다. 거절 처리는 기다리는 시간과 보유하는 FD 수를 제한하도록 설계한다.

**완료 기준과 최소 검증** · 관측 결과를 기록하고, 수정이 필요하면 같은 사례로 전달 완료를 한 번 확인한다. 한 사례의 성공은 그 조건에서의 결과로 기록한다. `-q 1024` 기본값 변경과 다중 부하 재실행은 이 진단 범위 밖이다.

## 진단 결과

Linux Docker에서 정상 GET 요청 하나가 서버의 TCP 소켓에 도착한 뒤 테스트 대역이 `threadpool_submit()`에서 거절을 반환하도록 했다. 이후에는 실제 accept 루프의 503 송신과 종료 코드를 사용했다. 클라이언트는 `HTTP/1.1 503 Service Unavailable`, 헤더 끝, 선언된 본문 33바이트 전체를 받았다. 그다음 읽기에서 TCP 리셋이 관측됐다.

이 사례에서는 응답 본문 손실이 없어 거절 경로와 기본 큐 크기 64를 유지한다. 리뷰어의 고부하 실행 원본 로그가 제공되지 않아 그 타임아웃의 원인은 미확인이다.

## 후속 변경

리뷰어의 추가 측정으로 원인이 확인됐다. 기본값(`-t 8 -q 64`)에서 동시 접속이 72를 넘는 `ab -c 80`, `ab -c 100`은 타임아웃으로 중단됐고, 같은 코드를 `-q 1024`로 띄우면 `ab -c 100`이 실패 0건으로 끝났다. 큐는 fd만 담으므로 기본 큐 크기를 1024로 올렸다. 최종 코드에서 동시 100·256 연결 모두 실패 0건이다.

## 후속 변경 2 (503 전달 보강)

큐를 1024로 늘린 뒤에도 `-q 16`처럼 큐가 작으면 `ab -c 200`이 타임아웃으로 멈췄다. 같은 조건에서 503 경로만 "송신 종료 후 입력을 버리고 close"로 바꾼 컨테이너 실험에서 멈춤이 사라져, 요청을 읽지 않은 채 close해서 생기는 RST가 원인으로 확인됐다.

1. accept 루프가 503을 보낸 연결을 최대 64개까지 poll 목록에 두고, 클라이언트가 닫거나 1초가 지나면 close한다. 워커를 쓰지 않고 accept도 막지 않는다.
2. 목록이 가득 차면 accept를 멈추고 새 연결을 커널 listen backlog에 둔다.
3. 시작할 때 큐 크기가 열린 파일 한도를 넘으면 soft 한도를 올리고, 안 되면 큐를 줄이고 경고한다. 리뷰에서 지적된 "fd 한도 1024·256에서 큐가 차기 전에 accept가 EMFILE로 실패하는 문제"를 막는다.

결과: `-q 16`에서 `ab -c 200`, `-c 1000`이 모두 완료되고 넘친 연결은 503을 받는다. `ulimit -n 256`에서도 accept 실패 없이 완료된다. `functional.sh`에 워커 1개·큐 1개 서버로 503 응답 전체 전달을 확인하는 사례를 추가했다.
