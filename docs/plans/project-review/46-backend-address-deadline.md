# 46. 한 호스트의 여러 IP에 연결 시간 배분

기준 `dev@37a55e8` · 우선순위 3 · 리뷰 2 · 반영 완료

## 작업 범위

Reverse Proxy는 설정에 나열된 백엔드별로 마감을 나눈다. 그 아래의 `connect_for_route()`는 DNS가 반환한 모든 주소에 같은 마감을 넘겨, 첫 주소가 시간을 다 쓰면 다음 주소를 시도할 수 없다. 수정 범위는 DNS 조회가 성공한 뒤부터 TCP 연결이 성립할 때까지다. Forward Proxy도 같은 연결 함수를 사용한다. [주소별 연결](../../../src/net.c) · [백엔드별 예산](../../../src/proxy.c) · [Forward 호출 경로](../../../src/forward_proxy.c)

## 구현 순서와 경계

1. DNS가 반환한 주소 순서를 따른다. 각 시도 직전에 상위 마감과 종료 유예를 반영한 남은 시간을 남은 주소 수로 나눈다. 계산은 단조 시계를 사용하고, 밀리초 반올림으로 상위 마감을 넘지 않게 한다. 마지막 주소와 단일 주소는 남은 시간을 모두 쓸 수 있다. [마감 도우미](../../../src/deadline.c)
2. 현재 주소가 즉시 거부되거나 자기 몫의 마감에 도달하면 소켓을 닫고 다음 주소의 예산을 다시 계산한다. 연결 성공 시 해당 소켓 하나를 넘기고, 전체 예산이 소진되면 시간 초과로 끝낸다. DNS 비용도 원래 예산 안에 포함한다.
3. 주소별 시도는 백엔드 한 곳에 대한 연결 시도 안에서 끝낸다. 라운드로빈·쿨다운은 기존 백엔드 단위로 판단하고, 요청을 쓴 뒤에 다른 IP로 재전송하는 경로를 만들지 않는다. 주소 목록의 소유권은 41번 규약을 따른다. [소유권 규약](41-dns-result-ownership.md)

## 완료 기준과 최소 검증

`test_proxy_relay`에 주소 두 개를 반환하는 조회 대역과 주소별 연결 시도를 관찰할 수 있는 작은 테스트 지점을 사용한다. 첫 시도는 배정 마감에 시간 초과하고 두 번째 시도는 성공하게 한다. 첫 마감이 상위 마감보다 이르고, 두 번째가 남은 예산 안에서 선택되며, 호출자가 성공한 소켓을 받는지 한 사례로 확인한다. 외부 DNS나 응답하지 않는 네트워크에 의존하지 않는다. 기존 백엔드 간 장애 전환 검사는 그대로 활용한다. [기존 연결·마감 검사](../../../tests/test_proxy_relay.c)

45·47번과 같은 작업에서 반영하면 `test_proxy_relay` 한 번으로 검증한다.

## 반영 결과

DNS가 반환한 목록을 처리하는 함수를 분리했다. 주소 선택 검사에는 조회 함수 대역 대신 두 주소의 목록을 직접 전달했다. 첫 시도가 배정된 마감에 시간 초과된 후 두 번째 시도는 원래 마감 안에서 실제 루프백 리스너에 연결했다. Linux Docker의 `test_proxy_relay`가 통과했다.
