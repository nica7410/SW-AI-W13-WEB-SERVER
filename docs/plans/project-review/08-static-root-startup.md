# 08. 잘못 지정한 정적 루트를 서버 시작 시 진단하기

외부 리뷰 3번 · 기준 커밋 `3a6b120` · 구현 순서 1/5

**구현 결과** · Docker의 실제 서버에서 명시한 루트 오타로 시작 실패, CGI 디렉터리 누락 시 정적 GET 200, 기본 정적 루트 누락 시 경고 후 기동을 확인했다.

Docker 복사본에서 `-r ./wwww`로 시작하자 오류 출력 없이 포트가 열렸고 정적 요청은 모두 404였다. 외부 리뷰가 확인한 결과다. 현재 `init_local_root()`는 경로를 여는 데 실패하면 HTTP 상태를 저장한다. `run_server()`는 이미 리스닝 소켓과 워커 풀을 만든 후에 이 함수를 호출하고 요청을 받는다. [서버 시작](../../../src/server.c) · [루트 초기화](../../../src/local_path.c)

## 확정 범위

| 시작 조건 | 서버 동작 |
|---|---|
| 명시한 `-r` 경로를 디렉터리로 열 수 없음 | 입력 경로와 OS 오류 원인을 stderr에 한 번 출력하고 포트를 열기 전에 실패 코드로 종료 |
| `-r` 생략, 기본 `./www` 사용 불가 | 경고 한 번 후 기동. 정적 루트 없이 실행하던 프록시의 호환성 유지 |
| 기본 또는 명시한 CGI 디렉터리 사용 불가 | 경고 한 번 후 기동. 정상 정적 요청과 프록시 요청은 계속 처리 |
| 루트가 유효하고 요청한 개별 파일이 없음 | 기존 파일 조회 경로에서 404 응답 |

## 구현 순서

1. CLI에서 `-r`가 실제로 주어졌는지 설정에 기록한다. 사용자가 직접 `-r ./www`를 쓴 경우에도 명시한 루트 정책을 적용한다. [인자 처리](../../../src/main.c) · [서버 설정](../../../src/server.h)
2. `init_local_root()`가 실패 시 원래 `errno`를 호출자에게 전달하게 한다. 요청 처리용 HTTP 상태도 보존한다. 시작 메시지에는 역할, 입력 경로, 해당 오류의 설명을 넣는다. [루트 내부 API](../../../src/server_internal.h)
3. 라우팅 설정을 읽은 뒤, 소켓과 워커를 만들기 전에 루트를 연다. 이후 다른 초기화 단계에서 실패해도 이미 연 디렉터리 fd를 닫는다. README의 CLI 표에 위 시작 정책을 반영한다. [실행 옵션](../../../README.md#빌드--실행)

## 완료 기준과 최소 검증

실제 서버 시작 경로에서 정책이 갈리는 세 경우만 한 번씩 확인한다. 명시한 정적 루트가 없으면 프로세스 종료 코드와 경로가 포함된 진단을 확인한다. 유효한 정적 루트에 CGI 디렉터리만 없으면 경고 한 번과 정적 GET 200을 확인한다. 기본 `./www`가 없는 작업 디렉터리에서 `-r`를 생략하면 경고 후 기동하는지 확인한다. 권한 오류와 일반 파일 입력도 같은 디렉터리 열기 실패 경로를 쓴다.
