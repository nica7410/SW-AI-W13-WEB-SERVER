# 07. README에 부하·누수 검증 결과와 출처 기록

**진행 결과** · 외부 리뷰 수치를 옮겨 적던 표를 지우고, 최종 코드로 다시 측정한 [부하 결과](../../../README.md#측정-결과-최종-코드)와 [메모리 검사](../../../README.md#메모리-검사)로 바꿨다. `load.sh`는 동시 접속 수 목록과 keep-alive 여부를 받아 한 번에 측정하도록 확장했다.

과제에는 동시 요청 수별 처리량 측정과 메모리 검사가 있고, 발표에서도 그 결과를 README로 보여 준다. 현재 README에는 실행 방법과 일부 테스트 결과가 있다. [README 검증 절](../../../README.md) · [부하 스크립트](../../../tests/load.sh)

1. 기록마다 실행 주체, 실행 환경, 코드 상태, 명령·옵션, 결과를 확인 가능한 만큼 적는다. 외부 리뷰어의 원본, 컨테이너 복사본에만 적용한 패치, 로컬 작업 트리에서 직접 확인한 결과를 구별한다.
2. 부하 결과는 연결 재사용 여부와 동시 연결 수를 붙여 비교한다. 예를 들어 리뷰어가 보고한 `c=1`의 22.8건/초와 13,851건/초는 각각 원본과 임시 패치의 값이다. 요청 수나 오류 내역 등 빠진 정보는 미기재로 표시한다.
3. 누수 결과는 검사 도구, 실행한 대상, 관측한 오류 여부를 기록한다. 단위 테스트 결과와 서버 종료까지 관찰한 결과를 구분하고, 원본 로그가 없으면 리뷰어가 보고한 범위로 표현한다. 후속 수정본에 과거 측정값을 그대로 붙이지 않는다.

**완료 기준과 최소 검증** · 독자가 각 수치의 실행 조건과 코드 상태를 식별할 수 있으면 완료다. README diff와 사용한 기록을 대조한다. 이 문서 작업을 위해 부하·sanitizer를 다시 실행하거나 `load.sh`를 확장할 필요는 없다.
