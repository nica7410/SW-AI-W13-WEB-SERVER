# 31. 워커 양보 시 오류 응답도 전송을 마치고 연결 닫기

우선순위 2 · 리뷰 ③ · 구현 완료 · 기준은 `dev`의 `01a822e`에 26~29번을 반영한 작업 트리다.

## 문제와 적용 범위

`handle_connection()`은 대기 중인 연결에 워커를 양보하기로 하면 현재 응답을 보낸 뒤 송신 방향을 닫고 남은 입력을 최대 50ms 동안 읽는다. 그런데 요청 파싱에 성공한 뒤 `dispatch()`가 404나 403을 반환하면 오류 응답을 쓰는 분기로 들어간다. 이때 파서 거절을 뜻하는 `rejected`는 거짓이어서 정리 절차가 빠진다. 커널에 후속 입력이 남아 있으면 곧바로 소켓을 닫는 과정에서 마지막 응답 전달에 영향을 줄 수 있다. [연결 처리 루프](../../../src/server.c) · [워커 양보 정책](03-keepalive-worker-fairness.md)

## 구현 순서

1. 오류 응답이 필요한 경우 먼저 `send_request_error()`를 호출하고 그 송신 결과를 얻는다. 일반 응답과 오류 응답이 같은 지점에서 연결 정리 여부를 결정하도록 이 부분을 묶는다.
2. 송신에 성공하면 파서가 거절한 요청에는 250ms, 워커가 양보한 요청에는 50ms를 한도로 기존 `linger_close_input()`을 한 번 호출한다. 송신 실패는 기존 연결 종료 경로로 보내고, 양보하지 않은 일반 404는 요청의 keep-alive 정책을 따른다. 변경 대상은 현재 응답의 마무리 분기다.

## 완료 기준과 최소 검증

`test_server_edges`에서 오류 응답 송신과 연결 정리를 담당하는 내부 함수를 소켓 쌍으로 직접 확인한다. 기존 단위 테스트에서 `handle_connection()`만 호출하면 워커 풀이 비어 있어 양보 분기에 들어갈 수 없으므로, 실제 워커가 호출하는 마무리 함수를 내부 헤더로 공유한다. [서버 내부 인터페이스](../../../src/server_internal.h) · [서버 경계 테스트](../../../tests/test_server_edges.c)

검사는 양보가 결정된 요청의 404 한 건으로 충분하다. 상대 소켓에 소량의 후속 입력을 넣고 송신 방향을 닫은 뒤 마무리 함수를 호출한다. 클라이언트가 `Connection: close`와 선언된 길이만큼의 404 본문을 받고, 함수 반환 직후 서버 소켓에서 잔여 입력 없이 EOF가 확인되면 통과다. 이 관찰로 오류 응답 송신과 입력 정리를 함께 검증할 수 있다. 구현 후 Linux Docker에서 `test_server_edges`만 한 번 실행한다.

## 반영 결과

오류 응답을 보낸 뒤에도 워커가 미리 정한 정리 시간을 적용하도록 `finish_request()`에서 송신 결과를 확인한다. Linux Docker(`gcc:14`)에서 `test_server_edges`가 통과했다. 양보한 연결의 404 응답에는 `Connection: close`와 선언한 길이만큼의 본문이 있었고, 서버 소켓은 남은 입력을 모두 읽은 뒤 EOF에 도달했다.
