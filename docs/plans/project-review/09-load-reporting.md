# 09. 부하 측정 실패와 HTTP 상태를 결과에 표시하기

외부 리뷰 4번 · 기준 커밋 `3a6b120` · 구현 순서 2/5

**구현 결과** · 고정된 `ab` 출력 네 가지로 도구 실패, 필수 지표 누락, 비-2xx 필드 생략, `failed`와 `non_2xx`의 중복 집계를 확인했다.

외부 리뷰에서는 대상 서버가 꺼져 있을 때 결과의 숫자들이 비었는데도 스크립트가 코드 0으로 끝났다. 별도의 과부하 실행에서는 503의 본문 길이가 200과 달라 일부 응답이 `Failed requests`의 길이 오류에도 집계됐다. 현재 스크립트는 `ab` 출력을 `awk`에 넘기면서 앞 명령의 종료 상태를 잃고, 필수 지표가 없어도 요약 줄을 출력한다. [부하 스크립트](../../../tests/load.sh)

## 확정 범위

`ab`를 실행할 수 없었거나 측정 결과를 해석할 수 없으면 해당 조건의 실행을 실패로 끝낸다. 측정을 완료한 경우 처리량, `failed`, `non_2xx`, 최장 지연을 각각 표시한다. `failed`와 `non_2xx`에는 같은 요청이 들어갈 수 있다. 두 값을 더해 총 실패 수를 계산하지 않는다. 정상적으로 끝난 과부하 측정에서도 503 수를 포함하는 지표를 읽을 수 있어야 한다.

## 구현 순서

1. `ab`의 종료 상태를 확인한 뒤 성공한 출력만 파싱한다. 파이프라인을 유지하는 경우 `pipefail`을 적용한다. 실패하면 해당 동시 접속 수와 도구의 오류 메시지를 stderr에 남기고 0이 아닌 코드로 종료한다. 그 조건의 성공 요약은 도구와 파서 양쪽이 성공한 뒤에만 출력한다.
2. `Requests per second`, `Failed requests`, 최장 지연의 숫자를 확인한다. 값 0은 유효하고, 필수 값의 누락은 파싱 오류다. `Non-2xx responses`는 정상 출력에서도 생략될 수 있으므로 그때만 0으로 채운다. `non_2xx`는 모든 비-2xx 응답 수로 표기한다.
3. README에 각 지표의 의미와 중복 가능성을 적는다. 외부 리뷰에서 기존 표는 503이 없던 실행으로 확인했으므로 수치는 유지한다. `wrk` 대체 경로는 자체 결과 출력과 종료 상태를 사용한다. [검증 문서](../../../README.md#검증)

## 완료 기준과 최소 검증

임시 `PATH`에 둔 가짜 `ab`의 고정 출력으로 스크립트 자체를 검사한다. 도구 실패와 필수 값이 빠진 성공 출력은 각각 비정상 종료하고 빈 요약을 남기지 않아야 한다. 정상 출력에서는 `Non-2xx` 생략 시 0을, 길이 오류와 비-2xx가 함께 있는 표본에서는 두 원래 수치를 각각 표시해야 한다. 실제 서버에 부하를 줄 필요가 없다.
