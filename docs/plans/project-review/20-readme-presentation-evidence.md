# 20. README 첫 화면에서 요구사항과 검증 근거 연결하기

우선 작업 2 · 외부 제안 9번 및 1번의 검증 기록 · 기준 커밋 `fb656d0` · 반영 완료

**반영 결과**

README의 설계 표에 다섯 요구사항의 구현 파일과 대표 검사를 연결했다. 기존 흐름도와 처리 범위 절을 활용하고 `fb656d0`의 Ubuntu CI 실행을 README와 13번 기록에 연결했다.

README 첫머리에 설계 표와 요청 처리 흐름도가 이미 있다. 발표자가 찾기 어려운 것은 “이 요구사항은 어느 코드가 담당하고 어떤 검사로 확인했는가”라는 연결이다. 기존 흐름도를 활용해 4분 발표에서 한 번에 따라갈 수 있는 분량으로 정리한다. [설계 표](../../../README.md#설계) · [요청 처리 흐름](../../../README.md#요청-처리-흐름)

## 작업 범위와 순서

1. 첫머리의 표를 다듬어 TCP 수락과 동시성, HTTP 파싱과 응답 경계, 정적 파일과 CGI, Forward·Reverse Proxy, 종료와 자원 회수를 각각 구현 위치 및 대표 검사와 연결한다. 수치와 옵션의 상세 설명은 기존 절에 연결한다. [기능 검사](../../../tests/functional.sh) · [종료 검사](../../../tests/test_shutdown.py)
2. 설계 선택은 실제 요청 흐름으로 설명한다. 워커 수가 제한된 스레드 풀에서 왜 유휴 keep-alive 연결을 양보하는지, 어느 요청부터 503이 되는지, 두 프록시가 각각 누구를 대신하는지를 담는다. 캐싱은 과제의 선택 항목으로 표시한다.
3. `fb656d0`의 Ubuntu CI에서 기능·종료 검사가 통과한 실행 링크를 검증 절과 13번 기록에 반영한다. macOS 상태는 19번에서 확보한 근거에 맞춰 적는다. 19번 러너가 대기 중이어도 README 정리는 독립적으로 진행할 수 있다. [13번 기록](13-ci-integration-tests.md) · [Ubuntu CI 실행](https://github.com/nica7410/SW-AI-W13-WEB-SERVER/actions/runs/45123268839)

## 완료 기준과 최소 검증

README 첫 화면에서 각 요구사항의 구현 파일과 대표 검사를 찾을 수 있고, 발표자가 기존 흐름도 하나로 설계 선택을 설명할 수 있다. 문서 diff와 링크를 확인하고, 성능 수치가 등장하는 곳은 기존 측정 표의 커밋·조건과 대조한다.
