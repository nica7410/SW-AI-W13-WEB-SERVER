# 06. URI 2KB의 의미와 414 경계 맞추기

**작업 유형** · 명세 확인 후 조건부 수정. 공통 헤더를 유지하는 범위에서 진행한다.

공통 헤더는 2048바이트를 넘으면 414라고 설명한다. 현재 배열은 종료 문자까지 포함해 2048바이트이므로 실제 URI는 2047바이트까지 저장한다. 파서는 정확히 2048바이트인 URI를 거절하며 기존 단위 테스트도 이 동작을 기대한다. [공통 헤더](../../../src/http_request.h) · [파서](../../../src/http_request.c) · [기존 경계값 테스트](../../../tests/test_http_request.c)

1. README에 현재 동작을 명시할 문구를 준비한다. “현재 요청 대상은 2047바이트까지 허용하며, 2048바이트부터 414를 반환한다.” 길이는 메서드와 HTTP 버전을 제외한 요청 대상의 바이트 수로 센다.
2. 2KB를 **저장 공간**으로 결정하면 README에 이 설명을 반영한다. **실제 요청 대상 2048바이트까지 허용**하는 계약이라면 공통 헤더를 바꿔야 한다. 그 경우 URI·경로·쿼리 배열과 정적 경로 디코딩 및 Forward Proxy 경로 버퍼까지 함께 맞추는 별도 변경으로 진행한다. 현재 배열에서 비교 연산만 완화하면 종료 문자 공간이 부족하다.

**완료 기준과 최소 검증** · 2047·2048·2049바이트의 기대 결과를 선택한 계약과 일치시킨다. 문구만 바뀌면 diff 확인으로 끝낸다. 허용 길이를 실제로 변경할 때만 해당 경계 사례를 보강하고 영향을 받는 최소 테스트를 선택한다.

## 반영 결과

사용자 결정에 따라 README에는 현재 구현의 경계를 기록했다. 문법상 유효한 요청 대상의 길이 검사에서 2047바이트는 통과하고 2048바이트와 2049바이트는 414가 된다. 파서의 비교식과 배열 크기를 대조했다. 2KB는 저장 공간(종료 문자 포함)의 의미로 확정한다.
