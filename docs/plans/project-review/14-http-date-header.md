# 14. 원 서버 응답과 프록시 중계에 HTTP Date 적용하기

우선 작업 2 · 외부 리뷰 5번의 Date 항목 · 기준 커밋 `ad86c5f` · 구현 완료

**반영 결과**

정적·오류 응답에는 Date를 생성하고 CGI·프록시 최종 응답에는 원래 Date를 한 번만 전달하거나 누락된 값을 보완한다. 일반 빌드의 `test_server_edges`와 `test_proxy_relay`가 통과했다.

현재 정적 파일과 로컬 오류 응답을 만드는 `send_headers()`는 Date를 생성하지 않는다. CGI와 프록시는 별도의 함수에서 응답 헤더를 전송하므로 두 경로가 모두 작업 대상이다. [로컬 응답](../../../src/http_response.c) · [CGI·프록시 응답](../../../src/response_stream.c)

## 확정 범위

| 응답 경로 | 적용할 동작 |
|---|---|
| 서버가 직접 만드는 정적·오류 응답 | 시계가 있는 원 서버의 2xx·3xx·4xx에는 Date가 필요하다. 구현을 단순하게 유지하기 위해 이 경로의 최종 5xx에도 생성한다. HEAD에도 같은 헤더를 보낸다. |
| CGI 최종 응답 | 최종 상태와 CGI 헤더를 읽은 뒤, 클라이언트에 내보낼 Date가 없으면 생성한다. 기존 단일 Date를 전달할 때에는 한 번만 출력한다. |
| Forward·Reverse Proxy의 최종 응답 | 전달할 Date가 있으면 원래 값을 유지한다. 없으면 원 서버의 최종 헤더를 받은 시각을 기록해 전송할 헤더에 추가한다. 원 서버의 5xx를 전달하는 경우도 포함한다. |
| 서버가 보내는 중간 응답 | 기존 `100 Continue` 생성 경로를 사용한다. 1xx의 Date 생성은 선택 사항이다. |

HTTP 시각에는 UTC 달력 시각을 사용한다. 단조 시계는 요청·응답 마감 계산에 계속 사용한다. 생성 형식은 영어 요일과 월, 두 자리 일자, 네 자리 연도, GMT를 사용하는 IMF-fixdate다. [RFC 9110 §6.6.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-6.6.1) · [HTTP 날짜 형식](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.7)

## 구현 순서

1. 호출자가 준 시각을 호출자 버퍼에 기록하는 포매터 하나를 두 경로에서 공유한다. 워커끼리 정적 버퍼를 공유하지 않도록 `gmtime_r()`와 고정된 영문 이름을 사용한다. 시각을 얻거나 변환하는 데 실패하면 임의의 날짜를 만들지 않는다.
2. 정적 응답과 로컬 오류에서는 헤더 묶음을 만들 때 Date를 넣는다. CGI·프록시에서는 헤더 이름의 대소문자를 무시하고 실제로 전달할 필드를 기준으로 판단한다. 예를 들어 `Connection` 옵션으로 제거되는 Date가 누락 보완을 막아서는 안 된다. 최종 헤더 쓰기 전에 판단을 끝내고 기존 본문 경계와 응답 마감을 따른다.

## 완료 기준과 최소 검증

기존 `test_server_edges`의 정적·CGI 응답 검사를 보강해 Date 한 개와 본문 보존을 확인한다. 같은 테스트 파일에서 고정 시각 하나의 포맷 결과를 비교한다. `test_proxy_relay`에서는 기존 두 정상 응답에 Date를 각각 제공하거나 생략해 원래 값 보존과 누락 보완을 확인한다. 구현 후 두 테스트 실행 파일만 한 번씩 실행한다. [서버 경계 검사](../../../tests/test_server_edges.c) · [프록시 검사](../../../tests/test_proxy_relay.c)
