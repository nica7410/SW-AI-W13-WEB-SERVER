# 50. 최소 연결 큐를 확보할 수 없으면 기동 거부

기준 `dev@018085b` · 우선순위 P2 · 구현 및 검증 완료

## 작업 범위

서버가 잡는 FD 예약량은 `워커 수 × FDS_PER_WORKER + FD_RESERVE`다. 기본 워커 8개에서는 예약량이 160이고, 큐 한 칸까지 포함한 최소 한도는 161이다. 지금은 soft limit 상향을 시도한 뒤에도 한도가 예약량 이하면 `fit_queue_to_fd_limit()`이 큐 크기 1을 반환한다. 이 경우를 기동 오류로 처리해 운영자가 첫 요청을 받기 전에 설정 문제를 알 수 있게 한다. [FD 예산 계산과 서버 기동](../../../src/server.c)

1. 기존 상향 시도 후 실제 적용된 soft limit으로 판단한다. 요청한 큐까지 수용하면 요청값을 사용하고, 큐 한 칸 이상만 확보할 수 있으면 기존처럼 남은 용량으로 줄인다. 유한한 한도가 예약량 이하이면 실패를 반환한다.
2. 실패 메시지에 적용된 FD 한도, 설정된 워커 수, 필요한 최소 한도(`reserve + 1`)를 표시한다. 예를 들어 한도 64는 고정 예약량 96보다도 낮으므로 이때는 FD 한도 자체를 높여야 한다.
3. `run_server()`는 실패를 워커 풀 생성 전에 처리하고, 이미 연 리스닝 소켓과 루트 디렉터리를 기존 정리 경로에서 닫는다. CLI는 기존 기동 실패 규약대로 종료 코드 1을 반환한다. README의 `-q` 설명과 과부하 절에 큐를 줄여 기동할 조건과 기동을 거부할 경계를 명시한다. [CLI](../../../src/main.c) · [실행 옵션과 과부하 정책](../../../README.md)

## 완료 기준과 최소 검증

구현 후 Windows의 Linux Docker에서 서버 바이너리를 한 번 빌드한다. 서버 자식 프로세스에만 `RLIMIT_NOFILE`의 soft/hard를 같은 값으로 설정해 상향 결과가 실행 환경에 따라 달라지지 않게 한다. 워커 8개, 요청 큐 1024로 다음 두 경계를 각각 한 번 확인한다. [기존 서버 프로세스 검사 예시](../../../tests/test_shutdown.py)

| FD 한도 | 통과 기준 |
|---|---|
| 160 | 종료 코드 1. 표준 오류에서 실제 한도 160과 필요한 최소 한도 161을 확인한다. |
| 161 | 큐를 1로 줄였다는 진단이 나오고, 정적 GET 한 건이 200과 기대 본문을 반환한다. |

## 반영 결과

`run_server()`가 루트 디렉터리와 리스닝 소켓을 열기 전에 FD 예산을 확인하도록 했다. 예산 부족으로 종료할 때는 정리할 서버 자원이 없다. README에 큐를 줄여 기동하는 조건과 최소 한도를 추가했다.

Linux Docker에서 [기동 경계 검사](../../../tests/test_shutdown.py)의 `test_startup_fd_budget()`를 한 번 실행했다. 한도 160에서는 종료 코드 1과 워커 8개에 필요한 최소 한도 161을 확인했다. 한도 161에서는 큐가 1024에서 1로 줄었다는 진단을 확인했고, 정적 GET 한 건이 200과 파일의 전체 내용을 반환했다.
