# 36. 잘못 쓴 HTTP 버전을 400으로 처리

기준 `cd65525` · 우선순위 높음 · 리뷰 ⑧ · 구현 완료

## 수정 범위

현재 `parse_request_line()`은 버전 문자열이 지원 목록과 다르면 형식 오류에도 505를 반환한다. 버전 표기 문법과 이 서버의 지원 목록을 순서대로 검사한다. [요청 라인 파서](../../../src/http_request.c) · [HTTP 버전 표기](https://www.rfc-editor.org/rfc/rfc9112.html#section-2.3)

## 구현과 완료 기준

1. 토큰 길이를 확인한 뒤 대소문자를 구분하는 `HTTP/`, 한 자리 십진수, 점, 한 자리 십진수 형식을 검사한다. 형식이 깨진 요청은 400이다.
2. 형식 검사를 통과하면 현재의 명시적 지원 목록인 HTTP/1.0·1.1과 연결 재사용 규칙을 적용한다. 다른 주 버전 및 현재 지원 목록 밖의 부 버전에 대한 기존 동작은 유지한다. 부 버전 협상 확대는 별도 기능이다.
3. 기존 `test_request_lines()`에 길이는 맞지만 숫자 위치에 문자가 있는 버전 한 건을 추가해 400을 확인한다. HTTP/2.0의 505와 HTTP/1.0·1.1의 성공은 같은 함수의 기존 검사를 사용한다. [요청 파서 테스트](../../../tests/test_http_request.c)

## 반영 결과

`test_http_request`에서 `HTTP/1.x`는 400, `HTTP/2.0`은 505, `HTTP/1.0`과 `HTTP/1.1`은 파싱 성공을 확인했다.
