**반영 결과**

일반 단위 검사 다음에 기능 검사와 종료 검사를 별도 단계로 추가했다. 두 스크립트는 로컬 Linux 컨테이너와 `fb656d0`의 GitHub Actions Ubuntu 러너에서 모두 통과했다. [원격 실행 기록](https://github.com/nica7410/SW-AI-W13-WEB-SERVER/actions/runs/45123268839)

현재 CI는 일반 빌드와 단위 테스트, ASan·UBSan 빌드와 단위 테스트를 실행한다. 라운드로빈, 장애 전환, 과부하 시 503 전달은 실제 서버를 띄우는 기능 스크립트에 있다. SIGTERM 유예 시간과 CGI 자식 회수는 별도 Python 검사에서 다룬다. [현재 CI](../../../.github/workflows/ci.yml) · [기능 검사](../../../tests/functional.sh) · [종료 검사](../../../tests/test_shutdown.py)

## 확정 범위와 구현 순서

1. 기존 Ubuntu 작업에서 일반 `make test`와 `make asan` 사이에 두 단계를 추가한다. 하나는 저장소 루트에서 `bash tests/functional.sh`, 다음은 `python3 tests/test_shutdown.py`를 실행한다. 단계 이름에 기능 검사와 종료 검사를 구분해 실패한 동작을 CI 화면에서 바로 찾을 수 있게 한다.
2. 두 단계는 앞서 만든 일반 서버와 CGI를 사용한다. 순차 실행하여 기능 스크립트가 띄운 프로세스와 포트를 정리한 뒤 종료 검사를 시작한다. 각 스크립트의 종료 코드를 CI 결과에 반영한다.
3. README의 CI 설명에 새 검사 두 개를 적는다. 기존 sanitizer 검사는 현재의 단위 테스트 범위를 유지한다. [빌드 대상](../../../Makefile) · [검증 안내](../../../README.md#검증)

## 완료 기준과 최소 검증

워크플로 diff에서 작업 디렉터리, 빌드 순서, 명령을 확인한다. 다음 정상적인 push 또는 PR의 CI 기록에 두 단계가 각각 한 번 나타나고 통과하면 실제 러너에서의 검증까지 완료한 것으로 기록한다. 그전에는 워크플로 검토와 러너 실행 결과를 구분한다. 로컬에서 전체 CI를 재실행할 필요는 없다.
