# 41. DNS 조회 실패 시 주소 목록의 소유권 정리

기준 `cd65525` · 우선순위 낮음 · 리뷰 ⑩ · 구현 완료

## 수정 범위

DNS 조회가 마감과 거의 동시에 끝나면 `resolve_until()`이 오류를 반환하면서 결과 주소 목록도 호출자에게 넘길 수 있다. 현재 유일한 호출자는 이를 해제한다. 내부 함수의 반환 규약을 ‘성공할 때만 주소 목록 전달’로 좁혀 이후 호출자도 같은 예외를 알아야 하는 부담을 줄인다. [조회와 연결 처리](../../../src/net.c)

## 구현과 완료 기준

1. 출력 포인터를 처음에 비운다. 작업 완료와 대기 결과를 기존 잠금 안에서 확인해 성공이면 목록을 한 번 넘기고, 대기가 실패했지만 작업이 이미 끝났으면 해당 목록을 조회 경로에서 한 번 해제한다.
2. 대기가 실패하고 작업이 진행 중이면 기존처럼 조회 스레드가 나중에 목록과 작업을 정리한다. 숫자 주소 경로도 같은 반환 규약을 따른다. 호출자가 관측하는 시간 초과·조회 오류, 재시도 예산, `peer_failed` 계산은 기존 동작을 따른다.
3. 코드 대조에서 성공, 완료 전 포기, 완료와 마감이 겹친 경우마다 주소를 해제할 주체가 하나인지 확인한다. 기존 `test_deadline()`은 조회 지연 후 시간 초과와 조회 스레드 종료를 검사한다. 이 검사가 정확히 같은 순간의 경합까지 재현한다고 기록하지 않는다. 33~35번과 함께 진행하면 동일한 `test_proxy_relay` 실행을 공유한다. [마감 테스트](../../../tests/test_proxy_relay.c)

## 반영 결과

주소 목록은 성공 시에만 호출자에게 넘긴다. 잠금 안의 소유권 분기를 대조해 대기 오류와 조회 완료가 겹치면 대기자, 조회 진행 중에 포기하면 조회 스레드가 해제함을 확인했다. `test_proxy_relay`의 지연 조회·마감 검사가 통과했다. 정확히 같은 순간의 경합은 코드 대조로 확인했다.
