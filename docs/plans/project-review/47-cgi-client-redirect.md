# 47. Location만 출력하는 CGI의 외부 리디렉션

기준 `dev@37a55e8` · 후속 작업 1 · 리뷰 4 · 반영 완료

## 작업 범위

현재 CGI 응답은 `Content-Type`이 없으면 모두 500이 된다. CGI가 유효한 절대 URI의 `Location` 한 개와 빈 줄만 출력한 경우를 외부 리디렉션으로 인식해 클라이언트에 302를 반환한다. [CGI 출력 처리](../../../src/response_stream.c) · [RFC 3875 §6.2.3](https://www.rfc-editor.org/rfc/rfc3875.html#section-6.2.3)

## 구현 순서와 경계

1. CGI 최종 응답을 분류할 때 외부 리디렉션 형식을 별도로 식별한다. 필드 이름은 대소문자를 구분하지 않는다. 값은 절대 URI 문법을 검사하고 선택적 프래그먼트를 보존한다. 목적지 조회나 서버 측 접속은 필요하지 않다.
2. 이 형식에서는 단일 필드와 빈 본문을 확인한 뒤 `302 Found`, 원래 `Location`, `Content-Length: 0`을 쓴다. CGI 출력의 끝을 확인할 때 기존 마감을 적용한다. 형식이 맞지 않으면 최종 응답을 쓰기 전에 기존 오류 경로로 돌려보낸다.
3. 일반 CGI 문서와 명시적으로 `Status`·`Content-Type`을 보낸 문서는 기존 경로로 처리한다. 내부 경로로 다시 라우팅하는 기능은 별도 호환성 과제로 둔다. README의 CGI 처리 범위에 이번에 지원하는 형식을 적는다. [기존 CGI 범위](cd65525-review-scope.md) · [README](../../../README.md)

## 완료 기준과 최소 검증

`test_proxy_relay`의 CGI 소켓 검사에서 절대 `Location` 단독 출력 한 건이 302, 동일한 목적지, 빈 본문으로 끝나는지 확인한다. 대조 사례로 로컬 경로의 `Location`만 보낸 경우에는 500이고 최종 응답을 쓴 바이트가 0인지 확인한다. 같은 필드 이름으로 두 형식을 구분할 수 있으며 실제 CGI 자식 기동은 필요하지 않다. [기존 소켓 검사](../../../tests/test_proxy_relay.c)

45·46번과 함께 반영하면 같은 테스트 실행을 공유한다.

## 반영 결과

CGI의 단일 `Location` 응답은 절대 URI와 빈 본문을 확인한 후 중계한다. Linux Docker의 `test_proxy_relay`에서 퍼센트 인코딩·쿼리·프래그먼트를 포함한 목적지, 302 상태와 길이 0의 빈 본문을 확인했다. 로컬 경로 단독 출력은 500을 반환했고 최종 응답 송신량은 0이었다.
