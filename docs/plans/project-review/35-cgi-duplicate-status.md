# 35. CGI가 Status를 두 번 보내면 500 반환

기준 `cd65525` · 우선순위 높음 · 리뷰 ⑤ · 구현 완료

## 수정 범위

CGI 필드 순회 중 `Status`가 다시 나오면 현재는 뒤쪽 값이 앞쪽 값을 덮는다. 한 출력에서 CGI 상태를 한 번만 지정하도록 검사한다. [CGI 출력 파서](../../../src/response_stream.c) · [RFC 3875 §6.3](https://www.rfc-editor.org/rfc/rfc3875.html#section-6.3)

## 구현과 완료 기준

1. CGI의 최종 헤더를 검사하는 범위에 `Status`를 이미 읽었는지 기록한다. 대소문자와 값의 동일 여부에 관계없이 두 번째 필드에서 500을 반환한다. 상태 생략 시 기본값 200과 단일 상태의 기존 문법을 적용한다.
2. 원 서버 상태는 HTTP 상태 줄에서 얻는다. 이 변경은 CGI 출력을 처리하는 분기에 둔다.
3. `test_proxy_relay`에서 정상 `Content-Type`과 두 개의 유효한 상태를 담은 CGI 출력 하나를 중계 함수에 전달한다. 500과 클라이언트 송신 0바이트가 완료 기준이다. 실제 CGI 프로세스를 기동할 필요가 없다. [중계 테스트](../../../tests/test_proxy_relay.c)

## 반영 결과

CGI의 `Status`는 한 번만 허용한다. `test_proxy_relay`에서 같은 값의 `Status`와 `sTaTuS`를 함께 보낸 경우 500과 클라이언트 송신 0바이트를 확인했다.
