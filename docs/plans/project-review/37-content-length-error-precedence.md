# 37. Content-Length 문법을 확인한 뒤 본문 상한 적용

기준 `cd65525` · 우선순위 높음 · 리뷰 ⑧ · 구현 완료

## 수정 범위

현재 파서는 숫자를 읽는 도중 1MiB를 넘으면 즉시 413을 반환한다. 이 때문에 이미 읽은 숫자가 크면 뒤에 비숫자가 있어도 잘못된 필드를 413으로 분류한다. [요청 헤더 파서](../../../src/http_request.c) · [본문 길이 규칙](https://www.rfc-editor.org/rfc/rfc9112.html#section-6.3)

## 구현과 완료 기준

1. 기존 필드 파싱과 헤더 길이 제한을 통과한 값을 대상으로, 비어 있거나 중복된 길이 필드의 기존 400 판정을 적용한다. 이후 값 전체가 십진 숫자인지 먼저 확인한다.
2. 유효한 숫자열만 본문 상한과 비교한다. 큰 값을 정수에 전부 담을 필요 없이 상한 초과가 확정되면 413을 반환한다. 선행 0을 포함해 상한 이내인 값은 실제 길이를 저장한다.
3. `test_headers()`에 숫자 접두사만으로 상한을 초과하고 뒤에 문자가 붙은 값 한 건을 추가한다. 기대값은 400이다. 정확히 1MiB의 성공, 그보다 큰 유효한 숫자의 413, 중복 필드의 400은 기존 사례로 확인한다. [요청 파서 테스트](../../../tests/test_http_request.c)

## 반영 결과

`test_http_request`에서 `99999999abc`는 400, `1048577`은 413, `1048576`은 정상 길이로 처리됐다.
