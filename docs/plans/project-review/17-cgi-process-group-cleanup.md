# 17. CGI 중단 시 같은 프로세스 그룹의 하위 작업까지 종료하기

선택 작업 · 셸 CGI가 실행한 하위 프로그램까지 관리할 때 · 외부 리뷰 6번 · 기준 커밋 `ad86c5f` · 구현 완료

**반영 결과**

중단 시 CGI 프로세스 그룹에 종료 신호를 보내고 직접 자식을 회수한다. `test_shutdown.py`에서 직접 자식이 먼저 끝난 뒤에도 하위 프로세스의 소켓이 닫혔고, 서버는 SIGTERM 후 5.04초에 정상 종료했다.

현재 서버는 `fork()`로 직접 실행한 CGI의 PID에 신호를 보내고 `waitpid()`로 회수한다. CGI가 셸 스크립트이고 다른 프로그램을 실행했다면 직접 자식에 보낸 신호가 그 프로그램에 전달된다는 보장은 없다. 기존 SIGTERM 검사는 직접 실행한 CGI의 종료까지 확인한다. 하위 프로세스 잔존은 이번 외부 리뷰에서 코드로 지적된 사항이며 실행 재현은 아직 기록되지 않았다. [CGI 실행과 회수](../../../src/cgi.c) · [현재 종료 검사](../../../tests/test_shutdown.py)

## 확정 범위

CGI 요청 하나에 전용 POSIX 프로세스 그룹 하나를 연결한다. 전체 응답 마감, 서버 종료 유예 만료, 중계 실패 또는 CGI 종료 대기 만료로 작업을 강제 중단할 때 같은 그룹에 남은 하위 작업에도 종료 신호를 보낸다. 직접 실행한 자식은 서버가 회수한다. 보장 범위는 해당 그룹 구성원까지이며, 별도 세션·그룹으로 독립한 프로세스를 추적하는 기능은 별도 과제다. 중계 30초와 공통 종료 유예 5초는 기존 정책을 따른다. [종료 정책](12-relay-and-shutdown-deadlines.md)

## 구현 순서

1. CGI 자식이 프로그램을 실행하기 전에 전용 그룹을 만들고, 부모는 정리 작업에 사용할 그룹의 식별자를 확인한다. 자식의 실행과 부모의 확인 순서가 뒤바뀌는 경우를 처리한다. 설정 실패는 기존 실행 오류 보고 경로로 전달한다.
2. 강제 정리에서는 요청 소유가 확인된 그룹에만 신호를 보낸다. 그룹이 성립하기 전 실패한 경우에는 직접 자식만 정리한다. 서버 자신의 그룹에 신호가 가거나, 자식을 회수한 뒤 재사용된 식별자로 신호를 보내는 일이 없도록 그룹 종료와 `waitpid()`의 순서를 정한다. 직접 자식이 먼저 끝났더라도 후손이 CGI 출력을 열어 둔 경우를 포함한다.
3. 워커가 소유한 fd와 직접 자식의 회수는 한 정리 경로에서 끝낸다. 정상 완료 시 응답 본문과 상태 코드 처리 방식은 기존 동작을 따른다.

## 완료 기준과 최소 검증

기존 종료 검사에 유한한 하위 프로그램 하나를 띄우는 CGI를 사용한다. 첫 응답과 하위 프로그램 시작을 확인한 뒤 SIGTERM을 한 번 보낸다. 서버가 기존 테스트의 허용 범위(4.5~6.5초)에 코드 0으로 끝나는지, 직접 자식이 회수됐는지, 같은 그룹의 하위 프로그램도 종료됐는지 한 실행에서 확인한다. 마지막 조건에는 테스트 프로세스가 관찰하는 별도 파이프의 EOF처럼 하위 프로그램만 보유한 자원을 사용한다. CGI 응답 소켓 EOF나 고아 프로세스의 PID 존재 여부만으로 하위 프로그램 종료를 판정하면 잘못된 결과를 얻을 수 있다. [기존 테스트](../../../tests/test_shutdown.py)
