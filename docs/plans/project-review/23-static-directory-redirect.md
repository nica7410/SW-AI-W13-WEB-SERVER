# 23. 끝 슬래시가 빠진 정적 디렉터리 요청을 301로 안내하기

선택 작업 · 하위 폴더를 사용하는 정적 사이트 시연 · 외부 제안 4번 · 기준 커밋 `fb656d0` · 구현 완료

**반영 결과**

열린 파일이 디렉터리인지 확인한 뒤 301을 전송한다. `test_server_edges`에서 GET·HEAD의 빈 응답 본문, 쿼리·인코딩 보존, 여러 선행 슬래시의 정리, 리다이렉트 목적지의 200 응답을 확인했다.

정적 루트 안에 `sub/index.html`이 있으면 `/sub/`는 페이지를 열지만 `/sub`는 디렉터리가 일반 파일 검사를 통과하지 못해 403이 된다. 브라우저가 하위 페이지의 상대 링크를 올바르게 해석하도록 실제 디렉터리의 기준 URL을 알려 준다. [경로 해석](../../../src/local_path.c) · [정적 파일 처리](../../../src/static_file.c)

## 작업 범위와 순서

1. 기존 루트 경계 검사와 파일 열기가 성공한 뒤 열린 파일의 `fstat()` 결과로 디렉터리를 구분한다. 정적 GET·HEAD에서 끝 슬래시가 빠진 실제 디렉터리에만 301을 보낸다. 이미 슬래시가 있는 경로는 기존 인덱스 탐색을 따른다. POST와 경로 검사 실패에는 기존 오류 처리를 적용한다.
2. `Location`은 같은 서버의 경로로 작성한다. 예를 들어 `/sub?lang=ko`는 `/sub/?lang=ko`가 된다. 원본 요청의 인코딩과 쿼리를 보존하고, 선행 슬래시가 여러 개여도 외부 호스트를 가리키는 URL이 되지 않게 한다.
3. 로컬 응답 작성 경로에 301 상태 문구와 `Location` 전송을 연결한다. 빈 본문과 `Content-Length: 0`을 사용하고 기존 Date, 연결 정책, 접근 로그에 실제 전송 상태가 반영되게 한다. README의 디렉터리 동작 설명도 갱신한다. [응답 헤더 작성](../../../src/http_response.c)

## 완료 기준과 최소 검증

기존 `test_server_edges`의 임시 정적 루트에 디렉터리와 인덱스를 둔다. 쿼리가 있는 GET의 301과 정확한 목적지, HEAD의 빈 본문, 목적지 GET의 200을 같은 사례에서 확인한다. 선행 슬래시가 여러 개인 요청의 목적지도 같은 서버 안에 머무는지 검사한다. 이 실행 파일 한 번으로 기존 루트 경계 동작까지 확인한다. [서버 경계 검사](../../../tests/test_server_edges.c)
