# 16. 반복해서 연결에 실패하는 백엔드를 잠시 제외하기

선택 작업 · 로드 밸런싱과 장애 복구를 시연할 때 · 외부 리뷰 3번 · 기준 커밋 `ad86c5f` · 구현 완료

**반영 결과**

여러 백엔드를 쓰는 경로에 5초 제외 기간과 단일 복구 시도를 적용했다. `test_proxy_relay`에서 대체 서버 선택, 제외·복귀, 중복 복구 방지, 동시 연결에서 로컬 오류가 다른 워커의 실패 판정을 가리지 않는 경우를 확인했다.

현재 Reverse Proxy는 첫 후보에 연결하지 못하면 같은 요청 안에서 다음 서버로 넘어간다. 다음 요청은 다시 라운드로빈 순서를 따른다. 두 서버 중 하나가 TCP 연결에 응답하지 않으면 그 서버가 첫 후보가 될 때마다 약 2.5초를 사용할 수 있다. 이번 개선의 목적은 이미 관찰한 연결 실패 때문에 뒤따르는 요청이 다시 기다리는 횟수를 줄이는 것이다. [현재 선택 로직](../../../src/router.c) · [연결 시도와 마감](../../../src/proxy.c) · [이전 장애 전환 계획](11-reverse-proxy-connect-budget.md)

## 확정 범위

- 같은 경로 규칙에 백엔드가 둘 이상일 때 후보별로 상태를 관리한다. DNS 조회 실패, 연결 거부, 연결 시도 시간 초과 등 해당 목적지와 연결을 맺기 전의 실패만 일시 제외 근거로 쓴다. 로컬 자원 부족, 서버 종료, 요청 전체 예산 소진, 연결 성공 뒤의 HTTP 오류는 백엔드 상태를 바꿀 근거에서 제외한다.
- 첫 제외 기간은 **5초**로 정한다. 이 값은 시연용 기본값이다. 제외 중에는 정상 후보끼리 라운드로빈을 적용하고, 기간이 지나면 실제 요청 하나가 그 서버의 연결을 다시 시도한다. 성공하면 복귀시키고 같은 유형의 연결 실패가 반복되면 제외 기간을 갱신한다.
- 시도할 후보가 전부 제외 중이거나 다른 워커가 복구 여부를 확인 중이면 이번 요청은 즉시 502로 끝낸다. 후보를 실제로 시도한 요청의 502·504 판정과 공통 5초 마감은 기존 규칙을 따른다. POST는 전송을 시작한 뒤 재시도하지 않는다. 단일 백엔드 규칙과 Forward Proxy에는 기존 연결 정책을 적용한다.

## 구현 순서

1. 라우팅 설정을 읽을 때 채우는 주소·포트와 워커가 갱신하는 상태의 수명을 구분한다. 단조 시계의 제외 만료 시각과 복구 확인 여부를 짧은 동기화 구간에서 읽고 쓴다. DNS와 소켓 연결 중에는 잠금을 풀고, 늦게 끝난 이전 시도가 더 최근의 상태 결정을 덮지 않게 한다. [라우팅 구조체](../../../src/router.h)
2. 현재 요청이 실제로 시도할 수 있는 후보 수로 남은 연결 시간을 나눈다. 후보를 선택할 때 다른 워커가 이미 복구 확인 권한을 가져갔다면 다음 후보로 진행한다. 실패를 처음 관찰하기 전에 동시에 시작한 요청은 각각 지연될 수 있음을 README에 적는다.

## 완료 기준과 최소 검증

기존 `test_proxy_relay`의 연결 대역과 제어 가능한 시각을 이용한다. 한 시나리오에서 첫 요청의 실패 후 대체 서버 성공, 제외 기간 중 실패 서버 호출 0회, 만료 후 한 번의 복구 연결과 정상 복귀를 순서대로 확인한다. 후보가 전부 제외된 상태와 동일 후보에 대한 두 번의 복구 권한 요청은 상태 전이 검사로 확인한다. 테스트 실행 파일은 한 번만 실행하며 실제 네트워크 장애나 부하 측정은 필요하지 않다. [기존 장애 전환 테스트](../../../tests/test_proxy_relay.c)
