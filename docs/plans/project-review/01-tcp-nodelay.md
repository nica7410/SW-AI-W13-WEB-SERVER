# 01. 작은 정적 응답의 keep-alive 지연 줄이기

**진행 결과** · 수락한 소켓에 옵션을 적용하고 같은 연결에서 정적 응답 두 건을 확인했다. [검증 기록](../../../README.md#측정-결과-최종-코드)

작은 정적 파일의 응답 헤더와 본문은 별도로 송신된다. 외부 리뷰에서는 같은 조건에서 `TCP_NODELAY`만 켰을 때 단일 연결의 처리량이 크게 개선됐다. 수정 범위는 서버가 수락한 클라이언트 TCP 소켓이다. [정적 파일 송신](../../../src/static_file.c) · [연결 수락](../../../src/server.c)

1. `run_server()`에서 `accept()`한 소켓을 워커 큐에 넘기기 전에 `IPPROTO_TCP`의 `TCP_NODELAY`를 활성화한다. 옵션 실패 시에도 기존 HTTP 송신 경로로 요청을 처리한다.
2. 기존 유휴 타임아웃, 소켓의 블로킹 모드, 부분 쓰기 처리와 프록시의 원 서버 연결 설정을 보존한다.

**완료 기준과 최소 검증** · Linux에서 실제 서버로 작은 정적 파일을 같은 연결에서 두 번 요청하는 한 사례를 사용한다. 그 연결에 대한 서버의 `setsockopt` 성공을 시스템 호출 기록으로 확인하고, 두 응답의 본문과 길이를 확인한다. 외부 리뷰의 초당 요청 수는 이 기능 검사의 합격 기준으로 사용하지 않는다.
