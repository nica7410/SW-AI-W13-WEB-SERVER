# 29. 제출 문서에 실제 CI 실행 결과 반영

문서 수정 계획 · 코드 작업과 독립 · 리뷰의 CI 기록 항목 · 기준 커밋 `01a822e`

## 정정할 기록

현재 README에는 이전 기준 커밋 `5f211d5`의 CI와 당시 로컬 Docker 검사 결과가 있고, macOS 네이티브 실행은 확인 대기로 표시돼 있다. 이후 `01a822e`에 대해 GitHub Actions 실행 `45129365577`이 성공했다. [README 검증 절](../../../README.md#검증) · [대상 커밋의 CI 실행](https://github.com/nica7410/SW-AI-W13-WEB-SERVER/actions/runs/45129365577)

| 러너 | 해당 실행에서 성공한 항목 |
|---|---|
| Ubuntu | 빌드, 단위 검사, HTTP·프록시 기능 검사, SIGTERM 종료 검사, ASan·UBSan 빌드와 단위 검사 |
| macOS | 네이티브 빌드와 단위 검사. 단위 검사에는 CGI 실행과 실행 파일 교체 후 403 검사가 포함된다. |

## 반영 순서와 완료 기준

1. README의 검증 절에서 커밋·실행 링크·플랫폼별 검사 범위를 위 기록에 맞춘다. 직접 수행한 Docker 결과는 실제 측정 커밋인 `5f211d5`에 귀속시킨다. [CI 작업 정의](../../../.github/workflows/ci.yml) · [CGI 검사](../../../tests/test_server_edges.c)
2. 25번 기록의 마지막 문장에는 후속 CI 링크를 덧붙여 로컬 검사 당시의 상태와 이후 macOS 확인 시점을 함께 남긴다. 성능 표와 과거 메모리 측정의 커밋·실행 조건은 당시 기록을 따른다. [25번 작업 기록](25-proxy-http-cgi.md)
3. 변경 후 문서 diff에서 SHA·링크·러너·검사 이름을 실제 실행 기록과 대조한다. 완료 기준은 독자가 어느 커밋이 어느 환경에서 어떤 검사를 통과했는지 원본 실행 한 건으로 확인할 수 있는 것이다. 26~28번 구현 결과는 그 변경을 포함하는 실행에서 별도로 기록한다.

## 반영 결과

GitHub Actions 실행 45129365577의 커밋 SHA, 두 러너의 성공 상태와 각 단계 이름을 대조했다. README와 25번 기록에 `01a822e`의 Ubuntu·macOS 검증 범위를 반영하고, `5f211d5`에서 직접 확인한 Docker 결과와 26~28번의 로컬 테스트에 각각 검증 대상을 표시했다. [CI 실행 기록](https://github.com/nica7410/SW-AI-W13-WEB-SERVER/actions/runs/45129365577)
