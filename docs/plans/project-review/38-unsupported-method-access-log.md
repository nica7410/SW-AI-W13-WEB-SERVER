# 38. 접근 로그에서 긴 미지원 메서드 식별

기준 `cd65525` · 우선순위 보통 · 리뷰 ⑧ · 구현 완료

## 수정 범위

`PROPFIND`처럼 8자 이상인 유효한 메서드 토큰은 501 처리 전에 요청 구조체에 복사되지 않아 로그에 `method=-`로 남는다. 어떤 요청이 거절됐는지 구분할 수 있도록 로그에 사용할 이름을 길이 제한 안에서 보존한다. [요청 파서](../../../src/http_request.c) · [접근 로그](../../../src/access_log.c)

## 구현과 완료 기준

1. 메서드 전체의 토큰 문법을 검사한 뒤 제한된 이름을 기록한다. 예를 들어 기존 메서드 배열을 16바이트로 두면 `PROPFIND` 전체를 담을 수 있다. 더 긴 이름은 끝에 생략 표시를 붙여 완전한 이름과 구분한다. 입력 크기에 따른 동적 할당은 필요하지 않다.
2. 지원 여부는 원래 토큰 전체를 기준으로 판단한다. GET·HEAD·POST의 의미와 미지원 요청의 501을 유지한다. CGI 환경 변수 버퍼 등 기존 이름 소비처의 크기도 함께 대조한다.
3. `test_request_lines()`에서 8자 메서드는 501과 전체 이름, 저장 한도를 넘는 메서드는 501과 끝이 표시된 널 종료 문자열을 확인한다. 기존 로그 함수가 이 필드를 직접 쓰므로 별도 서버를 띄울 필요가 없다. [요청 구조체](../../../src/http_request.h) · [파서 테스트](../../../tests/test_http_request.c)

## 반영 결과

`test_http_request`에서 `PROPFIND`와 16자 메서드 모두 501을 확인했다. 접근 로그가 읽는 필드에는 각각 전체 이름과 앞 12자 뒤에 `...`가 붙은 널 종료 문자열이 남았다.
