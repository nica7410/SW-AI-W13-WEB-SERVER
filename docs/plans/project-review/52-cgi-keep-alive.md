# 52. 길이를 명시한 CGI 응답의 연결 재사용

기준 `dev@50cf0ce`

## 작업 범위

CGI가 유효한 `Content-Length`를 명시하고 요청과 워커가 연결 유지를 허용하면 같은 TCP 연결에서 다음 요청을 받는다. 길이 0도 포함한다. CGI에 길이가 없거나 요청 또는 CGI가 `Connection: close`를 지정하면 해당 응답으로 연결을 끝낸다. 본문이 선언한 길이보다 짧거나 전송에 실패하면 연결을 닫는다.

## 구현 순서

1. CGI 헤더를 검사하는 응답 중계기에서 연결 정책을 결정한다. 응답 헤더에 그 결정을 쓰고 워커는 중계 성공 여부와 같은 결정을 사용해 다음 요청을 받을지 정한다.
2. 기존 요청 버전별 정책, 워커 양보와 종료 처리, CGI 마감, 프록시의 연결 종료 정책을 적용한다. 공개 `serve_cgi()`의 시그니처와 핸들러 반환 규약을 보존한다.
3. README와 CGI 인터페이스 주석에 새 정책을 반영한다.

## 완료 기준과 최소 검증

실제 TCP 서버에서 길이를 명시한 CGI 응답 뒤 같은 소켓으로 다음 요청의 응답을 받는다. 길이가 없는 응답의 EOF와 선언한 길이보다 짧은 응답의 연결 종료도 확인한다. 기존 마지막 CGI 응답 검사는 클라이언트가 명시적으로 종료를 요청하도록 조정하고, 본문 전체와 EOF를 확인한다. 서버 실행 파일을 빌드하고 이 동작에 해당하는 테스트 함수만 실행한다.

## 반영 결과

워커의 연결 재사용 허용 여부를 CGI 중계기에 전달한다. 중계기는 헤더를 검증하고 최종 연결 정책을 워커에 돌려준다. 워커는 중계가 성공하고 연결 재사용이 허용된 경우 다음 요청을 읽는다. README, CGI 헤더 주석, 로컬 동작 설명서에 이 조건을 반영했다.

Linux Docker에서 `test_cgi_keep_alive()`와 `test_completed_cgi_close()`가 통과했다. 같은 소켓에서 본문 2바이트, 0바이트, 길이 미지정 CGI 응답을 차례로 받고 마지막에 EOF를 확인했다. CGI가 종료를 지정한 경우와 본문이 선언보다 짧은 경우에도 EOF를 확인했다. 클라이언트가 종료를 요청한 기존 사례에서는 1,179,648바이트 본문 전체를 받은 뒤 연결이 닫혔다.
