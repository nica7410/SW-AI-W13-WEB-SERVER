# 42. README에 청크 제한 순서·모듈·검증 버전 명시

## 수정 범위

README만 읽어도 요청이 어떤 제한에 먼저 걸리는지, 어떤 버전에서 각 검사를 했는지 판단할 수 있도록 다음 부분을 바로잡는다. [README](../../../README.md)

1. 청크 크기 줄은 크기 숫자·확장·CRLF를 합쳐 8,192바이트까지 읽는다. 줄 제한을 먼저 초과하면 400이다. 각 줄이 유효한 뒤에 요청 전체 확장 합계를 검사해 8,192바이트 초과에 413을 반환한다. 본문 상한 1MiB는 별도다. [요청 파서](../../../src/http_request.c) · [28번 합산 기준](28-request-chunk-extension-limit.md)
2. 모듈 목록에 `src/access_log.{c,h}`를 넣는다. 라우팅 예시에는 쿼리를 뺀 경로 문자열의 최장 접두사를 사용한다는 점, 중복 접두사 경고가 실제 구현됐으면 첫 규칙 선택을 적는다. `-f`는 내부 주소를 포함해 요청 목적지로 연결할 수 있다는 점도 기존 사용법에 한 줄로 설명한다.
3. 검증 절에 `cd65525`의 성공한 실행과 러너별 검사 범위를 명시한다. 이전 부하·메모리 수치에는 당시 버전과 조건을 붙여 둔다. 33번 이후 변경에 대해서는 해당 변경을 포함한 검사 결과만 기재한다. [기준 커밋 CI](https://github.com/nica7410/SW-AI-W13-WEB-SERVER/actions/runs/45135579500) · [CI 정의](../../../.github/workflows/ci.yml)
