# 05. 병렬 make에서도 sanitizer 정리가 빌드보다 먼저 끝나게 하기

**진행 결과** · 재귀 make 두 단계로 변경했다. 병렬 드라이런에서 정리 순서와 컴파일·링크 플래그를 확인했다. [검증 기록](../../../README.md#메모리-검사)

변경 전에는 `asan: clean all test`가 세 대상을 같은 수준의 선행 조건으로 선언해 병렬 빌드에서 정리와 컴파일이 겹칠 수 있었다. 이제 첫 번째 하위 make가 정리를 끝내면 두 번째 하위 make가 sanitizer 빌드와 테스트를 시작한다. [Makefile](../../../Makefile)

1. `asan` 레시피에서 재귀 `$(MAKE) clean`을 먼저 완료하고, 성공한 뒤 두 번째 `$(MAKE)`로 `all test`를 수행한다. 같은 레시피의 순서를 이용해 두 단계를 분리한다.
2. 두 번째 호출에 기존 AddressSanitizer·UBSan 컴파일 및 링크 플래그를 전달한다. 프로젝트 include 경로, pthread 옵션, 호출자가 지정한 경고 플래그와 make의 병렬 실행 설정도 함께 보존한다.
3. 일반 `make`와 `make test`의 대상·의존 관계는 기존 방식을 따른다.

**완료 기준과 최소 검증** · 빌드 산출물이 없는 임시 복사본에서 `make -n -j2 asan` 한 번으로 하위 호출의 순서와 실제 컴파일·링크 명령에 전달되는 플래그를 확인한다. 이 검사의 결과는 빌드 순서에 대한 확인으로 기록한다.
