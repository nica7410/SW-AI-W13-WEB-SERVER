# 11. 첫 백엔드의 연결 시간이 초과돼도 다음 서버 시도하기

외부 리뷰 2번 · 기준 커밋 `3a6b120` · 구현 순서 4/5

**구현 결과** · `test_proxy_relay`에서 첫 연결의 시간 초과와 두 번째 연결 성공을 모의했다. 후보별 마감, POST 한 건 전달, 최종 200과 본문을 확인했다.

외부 리뷰에서는 두 백엔드 중 하나가 연결에 응답하지 않자 라운드로빈 순서에 따라 약 5초 후 504와 정상 200이 번갈아 나왔다. 현재 모든 `connect_until()` 호출은 동일한 최종 마감 시각을 받는다. 기존 기능 검사는 중지한 로컬 서버가 연결을 즉시 거부하는 경우를 다룬다. [Reverse Proxy](../../../src/proxy.c) · [연결 처리](../../../src/net.c) · [기능 검사](../../../tests/functional.sh)

## 확정 범위

Reverse Proxy가 한 요청에 쓸 수 있는 DNS 조회부터 최종 응답 헤더까지의 시간은 기존 5초다. 그 안에서 **아직 요청을 보내지 않은 백엔드 연결 시도**에만 개별 마감을 적용한다. 라운드로빈으로 첫 서버를 선택하고 같은 규칙의 후보를 한 번씩 순회한다. Forward Proxy는 단일 목적지에 기존 예산을 사용한다.

## 구현 순서

1. 요청 시작 시 단조 시계로 공통 마감을 한 번 정한다. 각 시도 직전에 남은 시간과 현재 후보를 포함한 남은 후보 수를 구한다. 시도 예산은 남은 밀리초를 후보 수로 나눈 값으로 정하고 최소 1ms, 최대 공통 마감으로 제한한다. 마지막 후보는 남은 시간 전부를 쓸 수 있다. 두 후보가 있는 요청의 첫 시도는 약 2.5초를 쓸 수 있으며 즉시 실패하면 남은 시간은 다음 후보가 쓴다.
2. 개별 마감은 해당 후보의 DNS와 TCP 연결에 함께 전달한다. 연결이 되면 요청 전송과 최종 응답 헤더 수신에는 원래의 **공통 마감**을 전달한다. 요청 전송을 시작한 뒤에는 POST 중복 실행을 막기 위해 다른 백엔드에서 다시 보내지 않는다. 응답 본문 수명은 [12번 계획](12-relay-and-shutdown-deadlines.md)에서 다룬다.
3. 모든 연결이 즉시 거부되는 등 시간 초과 없이 실패하면 502, 성공한 후보 없이 한 번이라도 연결 시간이 초과됐거나 공통 마감이 끝나면 504를 반환한다. 후속 후보의 성공은 앞선 시도의 시간 초과보다 우선한다. README에 시도별 마감과 공통 5초의 관계를 적는다. [프록시 시간 제한 API](../../../src/upstream.h) · [동작 설명](../../../README.md#처리-범위와-한계)

## 완료 기준과 최소 검증

기존 `test_proxy_relay`에 결정적인 사례 하나를 추가해 해당 실행 파일만 한 번 실행한다. 내부 테스트 대역이 첫 후보에 전달된 마감이 공통 마감보다 이른지 확인하고 `ETIMEDOUT`을 반환한다. 두 번째 후보는 미리 정상 응답을 넣은 소켓 쌍을 반환한다. 첫 후보부터 두 번째까지 한 번씩 호출됐는지, 두 번째에서 전달한 POST가 한 건인지, 클라이언트가 200과 본문을 받는지 확인한다. 실제 방화벽이나 운영체제의 TCP 재전송 시간에 의존하지 않는다.
