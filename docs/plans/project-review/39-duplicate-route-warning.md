# 39. 설정 파일에서 중복 라우팅 접두사 경고

기준 `cd65525` · 우선순위 보통 · 리뷰 ④ · 구현 완료

## 수정 범위

동일한 접두사가 두 번 선언되면 `match_route()`는 먼저 선언한 규칙을 사용한다. 기동은 성공하므로 운영자가 뒤쪽 규칙이 선택되지 않는 이유를 알기 어렵다. 파일을 읽을 때 정확히 같은 접두사를 발견하면 위치를 알려 준다. [설정 로더](../../../src/router.c) · [설정 형식](../../../conf/routes.conf)

## 구현과 완료 기준

1. `load_routes()`에서 형식이 유효한 규칙을 등록하기 직전, 이미 읽은 접두사와 바이트 단위로 비교한다. 일치하면 설정 파일명, 현재 줄 번호, 접두사와 첫 규칙이 우선한다는 내용을 표준 오류에 한 번 출력한다.
2. 지금처럼 규칙을 같은 순서로 등록하고 동일한 최대 규칙 수를 적용한다. 서로 다른 중첩 접두사는 정상 설정이다. 요청 시점의 문자열 최장 접두사 매칭, 백엔드 배열과 라운드로빈에는 경고 로직을 넣지 않는다.
3. `test_router`에서 서로 다른 백엔드를 가리키는 동일 접두사 두 줄을 임시 파일로 읽는다. 기동에 쓰이는 로더의 성공, 두 번째 줄에 대한 경고 한 건, 첫 규칙 선택을 확인한다. 중첩 경로 선택은 기존 검사가 있다. [라우터 테스트](../../../tests/test_router.c)

## 반영 결과

`test_router`가 실제 설정 로더로 두 줄을 읽었다. 두 규칙이 모두 등록됐고, 표준 오류에는 파일명과 2번 줄이 포함된 경고 한 건이 남았으며 요청은 첫 백엔드로 향하는 규칙을 선택했다.
