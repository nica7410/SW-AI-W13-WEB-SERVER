# 33. HTTP/1.0 원 서버 응답의 전송 인코딩 검사

기준 `cd65525` · 우선순위 높음 · 리뷰 ⑥ · 구현 완료

## 수정 범위

`response_until()`은 원 서버 상태 줄의 버전을 읽지만 최종 응답의 `Transfer-Encoding` 검사에서는 클라이언트 요청 버전만 확인한다. HTTP/1.1 클라이언트 앞에서 HTTP/1.0 원 서버가 보낸 잘못된 응답을 걸러내는 것이 목표다. [응답 중계](../../../src/response_stream.c) · [RFC 9112 §6.1](https://www.rfc-editor.org/rfc/rfc9112.html#section-6.1)

## 구현과 완료 기준

1. 각 원 서버 상태 줄을 읽을 때 그 응답의 버전을 식별한다. 중간 응답을 거쳐도 최종 검사는 해당 최종 상태 줄의 버전을 사용한다.
2. HTTP/1.0 원 서버 응답에 전송 인코딩 필드가 있으면 그 응답의 헤더를 클라이언트에 쓰기 전에 502를 반환한다. Forward와 Reverse 모두 기존 공통 경로를 사용한다. CGI는 자체 응답 헤더 규칙을 적용한다.
3. 기존 소켓 쌍 검사에 HTTP/1.1 클라이언트와 HTTP/1.0 원 서버 조합 한 건을 넣는다. 502와 클라이언트 송신 0바이트를 확인한다. 정상 HTTP/1.1 청크 응답은 기존 사례가 담당한다. [중계 테스트](../../../tests/test_proxy_relay.c)

## 반영 결과

`test_proxy_relay`에서 HTTP/1.1 클라이언트 앞의 HTTP/1.0 원 서버가 `Transfer-Encoding`을 보냈을 때 502를 반환하고 클라이언트에 쓴 바이트가 0임을 확인했다.
