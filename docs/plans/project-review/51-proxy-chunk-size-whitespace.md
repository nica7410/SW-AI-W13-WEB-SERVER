# 51. 원 서버 청크 크기 줄의 단독 후행 공백 정리

기준 `dev@018085b` · 우선순위 P3 · 구현 및 검증 완료

## 작업 범위

클라이언트 요청은 확장 없는 청크 크기 뒤에 스페이스나 탭만 남으면 400으로 거절한다. 원 서버 응답은 같은 줄을 수락하면서 공백까지 클라이언트에 전달한다. 원 서버와의 호환성을 유지하면서 두 프록시가 내보내는 크기 줄을 바로잡는다. [32번 요청 정책](32-request-chunk-size-whitespace.md) · [응답 중계](../../../src/response_stream.c)

1. `chunked_body()`에서 기존 `parse_chunk_size()`로 원본 줄을 먼저 검증하고 확장 길이도 받는다. 파싱이 성공하고 확장 길이가 0일 때만 줄 끝의 스페이스와 탭을 제거한다. 원래 16진수 표기와 선행 0은 보존한다. 공통 파서와 요청 파서의 수락·거절 기준은 그대로 적용한다. [공통 파서](../../../src/http_framing.c) · [요청 파서](../../../src/http_request.c)
2. 데이터 청크와 마지막 0 청크에 같은 처리를 적용한다. 유효한 확장이 있는 줄은 원문으로 중계하고, 마지막 청크는 기존처럼 트레일러 검사가 끝난 뒤에만 보낸다. 파싱이나 전송이 실패하면 현재 중계를 중단하는 기존 경로를 따른다. [트레일러 전달 정책](45-proxy-hop-trailers.md)

## 완료 기준과 최소 검증

기존 `test_forward_post_and_chunked_response()`의 원 서버 응답 한 건을 확장한다. 확장 없는 데이터 청크 끝에는 스페이스를, 마지막 0 청크 끝에는 탭을 두고, 기존의 인용된 확장·바이너리 본문·트레일러도 같은 응답에 포함한다. 수신 바이트를 기대값과 비교해 두 줄의 후행 공백만 사라지고 크기 숫자, 확장, 본문, 허용된 트레일러가 그대로인지 확인한다. [프록시 중계 검사](../../../tests/test_proxy_relay.c)

구현 후 Linux Docker에서 `build/test_proxy_relay`만 빌드해 한 번 실행한다.

## 반영 결과

두 프록시가 공유하는 `chunked_body()`에서 크기 줄을 검증한 뒤, 확장이 없을 때만 뒤의 스페이스와 탭을 제거한다. 데이터 청크와 마지막 청크 모두 원래 16진수 표기를 보존한다.

Linux Docker에서 `build/test_proxy_relay`를 한 번 실행해 통과했다. 수신 바이트를 비교해 데이터 청크의 `0A` 뒤 스페이스와 마지막 청크의 `00` 뒤 탭이 제거되고, 인용된 확장과 바이너리 본문, 허용된 트레일러가 보존되는 것을 확인했다.
