# 45. 프록시 응답의 연결 전용 트레일러 제거

기준 `dev@37a55e8` · 우선순위 2 · 리뷰 3 · 반영 완료

## 작업 범위

`chunked_body()`가 트레일러를 읽으면서 원래 응답 헤더의 저장소를 초기화한다. 원 서버가 `Connection`에 지정한 필드 이름을 끝까지 보존해 헤더의 `Trailer` 선언과 본문 뒤 실제 트레일러에 같은 규칙을 적용한다. 두 프록시가 공유하는 응답 중계 경로에서 처리한다. [응답 중계](../../../src/response_stream.c) · [RFC 9110 §7.6.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-7.6.1)

## 구현 순서와 경계

1. 초기 헤더의 모든 `Connection` 옵션을 트레일러 검사가 끝날 때까지 참조할 수 있게 한다. 기존 대소문자 무시·쉼표 목록 비교와 헤더 저장 한도를 활용한다. [필드 비교](../../../src/http_fields.h)
2. 응답 헤더를 쓰기 전에 각 `Trailer` 선언에서 연결 전용 이름을 뺀다. 남은 이름은 원래 순서대로 쓰고, 비게 된 선언은 생략한다.
3. 최종 트레일러의 문법과 기존 금지 필드 검사를 먼저 마친다. 그 뒤 원래 `Connection`이 지목한 일반 필드만 걸러내고 허용된 필드와 종료 청크를 중계한다. 금지된 프레이밍 필드나 잘린 입력에 기존의 전송 중단 규칙이 적용되도록 한다.

## 완료 기준과 최소 검증

`test_proxy_relay`의 기존 청크 응답 한 건에 연결 전용 필드와 일반 트레일러를 함께 둔다. 클라이언트가 받은 선언과 실제 트레일러 모두에서 전용 필드가 빠지고 일반 필드가 남으며, 기존 바이너리 본문과 종료 청크가 온전하면 통과다. [기존 응답 검사](../../../tests/test_proxy_relay.c)

45~47번을 연이어 구현할 때는 세 항목을 반영한 뒤 Linux Docker에서 `test_proxy_relay`를 한 번 실행해 결과를 공유한다.

## 반영 결과

원본 헤더와 트레일러를 각각 보관하고, `Trailer` 선언과 실제 트레일러에서 연결 전용 필드를 제거했다. Linux Docker의 `test_proxy_relay`에서 혼합 선언에는 `X-Sum`만 남았고 연결 전용 항목만 있던 선언은 사라졌다. 수신한 바이너리 본문, 허용된 트레일러, 종료 청크를 기대값과 대조했다. 46·47번과 실행 한 번을 공유했다.
