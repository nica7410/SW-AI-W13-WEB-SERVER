# 02. 요청 헤더 전체에 하나의 마감 시각 적용

**진행 결과** · 유휴 대기와 헤더 전체의 마감을 분리했다. 보강한 `test_http_request`를 한 번 실행해 통과했다. [검증 기록](../../../README.md#측정-결과-최종-코드)

변경 전에는 읽기 작업마다 수신 타임아웃이 따로 적용됐다. 이제 파서는 요청 라인을 읽기 시작할 때 정한 절대 마감 시각을 마지막 빈 줄까지 사용한다. RIO는 이미 버퍼에 들어온 줄에도 같은 마감 시각을 적용한다. [요청 파서](../../../src/http_request.c) · [RIO 구현](../../../src/rio.c) · [마감 시각 API](../../../src/deadline.h)

1. keep-alive 상태에서 다음 요청의 첫 바이트를 기다리는 기존 유휴 시간 5초를 보존한다. RIO 버퍼에 데이터가 있으면 즉시 시작하고, 비어 있으면 소켓이 읽기 가능한 시점부터 헤더 수신에 별도 5초를 부여한다. EOF와 유휴 만료는 기존 연결 종료 경로로 보낸다.
2. 요청마다 마감 시각을 한 번 계산한다. 내부 `read_line()`을 통해 요청 라인, 모든 헤더, 마지막 빈 줄에 같은 값을 전달하고 `rio_readline_until()`을 사용한다. 다음 요청에는 새 마감 시각을 부여한다.
3. 반환값과 `read_request()`의 공개 시그니처를 보존한다. 이 변경은 헤더까지 적용한다. POST 본문 읽기와 `100 Continue`의 동작은 기존 계약을 따른다.

**완료 기준과 최소 검증** · `test_http_request`에 헤더를 여러 줄 읽어도 마감 시각이 연장되지 않는 사례 하나를 보강한다. 짧은 테스트용 마감 시각을 내부에서 주입해 소켓 쌍으로 확인하고 해당 실행 파일만 한 번 실행한다. 정상 요청과 `100 Continue`는 같은 파일의 기존 검사를 활용한다.

## 후속 변경

헤더와 같은 방식으로 POST 본문 전체에도 5초 마감 시각을 적용했다(`rio_readn_until`). 본문을 4초에 1바이트씩 보내는 연결 8개가 워커를 모두 차지해도 9번째 정상 요청이 4.5초 후 응답을 받았다. 변경 전에는 25초 동안 응답이 없었다. 단위 테스트 `test_body_deadline`이 조금씩 도착하는 본문에서도 마감이 늘어나지 않음을 확인한다.
